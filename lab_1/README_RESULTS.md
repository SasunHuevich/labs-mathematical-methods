## Решение (HiGHS, лимит 600 с)

**Рабочий способ:** загрузка готовой модели из MPS.

```
Статус:     TIME_LIMIT (решатель остановлен по времени)
Z ≈        203.35   (лучшее найденное значение целевой функции)
Время:      ~606 с
```

При повторном запуске с лимитом 120 с получалось **Z ≈ 228.51** — это хуже, но тоже допустимое решение. Чем дольше работает HiGHS, тем ниже (лучше) значение Z.

> Полный оптимум за 10 минут может быть не достигнут. Для сдачи достаточно зафиксировать найденное Z, статус и время. При необходимости увеличьте `time_limit` до 3600 с или используйте Gurobi/CPLEX.

## Модель из txt-файлов (JuMP)

При сборке модели вручную из `c_y_j`, `C_x_ij`, `D_ir`, `Q_jr`, `J_for_G` и т.д. HiGHS за ~4 с возвращает:

```
Статус: INFEASIBLE
```

Отдельно проверено:

- только назначение VM → **OPTIMAL**
- назначение + ресурсы без узлов → **OPTIMAL**
- назначение + ресурсы + планы узлов → **INFEASIBLE**

Вывод: ошибка не в загрузке матриц, а в **интерпретации ограничений по узлам** (или в расхождении с тем, как собран MPS). Для получения численного ответа используйте **MPS** или сверьте постановку с PDF задания.
