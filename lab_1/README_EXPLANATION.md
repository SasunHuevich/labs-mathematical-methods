## 4. Математическая модель

### Индексы

- `i = 1…n` — VM (`n = 1160`)
- `j = 1…m` — серверы (`m = 76`)
- `r = 1…R` — ресурсы (`R = 4`)
- `g = 1…G` — узлы ЦОД (`G = 25`)

### Переменные

- `x_ij ∈ {0,1}` — VM `i` размещена на сервере `j` (допустимо только если `c_ij > 0`)
- `y_j ∈ {0,1}` — сервер `j` включён

### Целевая функция

В блокноте записано в «учебном» виде:

\[
\min Z = \alpha \sum_j c_j y_j + \beta \sum_{i,j} c_{ij} x_{ij}
\]

По эталонному **MPS** коэффициент при `y_j` фактически идёт с весом **β**, а не α (например, `0.012 × 80 = 0.96`).

### Ограничения

1. **Назначение:** каждая VM ровно на одном сервере  
   \(\sum_j x_{ij} = 1\)

2. **Ресурсы сервера:**  
   \(\sum_i d_{ir} x_{ij} \le q_{jr} y_j\)

3. **Конфликты** (пары 4–5, 6–7, 8–9 на одном сервере):  
   \(x_{i_1 j} + x_{i_2 j} \le 1\)

4. **План узла** `g` (серверы `j ∈ J_g`):  
   \(\sum_{j \in J_g} c_j y_j + \sum_{i,j \in J_g} c_{ij} x_{ij} = Plan_g\)

5. **Миграция:** не менее **582** VM остаются на исходных `(i, j)` из `x_ij_firstlyLocated.txt`:  
   \(\sum_{(i,j) \in \mathcal{L}} x_{ij} \ge 582\)

### Данные

| Файл | Содержимое |
|------|------------|
| `general_info.txt` | n, m, G, ε, α, β, Plan_g |
| `c_y_j.txt` | \(c_j\) |
| `C_x_ij.txt` | матрица \(c_{ij}\) (0 = запрет) |
| `D_ir.txt` | потребление \(d_{ir}\) |
| `Q_jr.txt` | ёмкость \(q_{jr}\) |
| `J_for_G.txt` | списки серверов по узлам |
| `x_ij_firstlyLocated.txt` | 792 исходных пары (i, j) |
| `model.mps` | полная модель (~60 тыс. бин. переменных) |

## 6. Код: модель JuMP

`build_vm_model(data)` создаёт MILP в HiGHS:

- бинарные `x[i,j]` и `y[j]`;
- для `c_ij = 0` добавляется `x[i,j] = 0`;
- цель и все ограничения из раздела 4.

**Альтернатива (рабочая):**

```julia
mps = read_from_file(joinpath("data", "model.mps"))
set_optimizer(mps, HiGHS.Optimizer)
set_attribute(mps, "time_limit", 600.0)
optimize!(mps)
```

## 7. Результаты проверки на вашем компьютере

### Загрузка

```
n=1160, m=76, |G|=25, исходных размещений=792
разрешённых пар (i,j): 59626
```

### Модель из txt

- Построение: **~0.7 с**, 88 236 переменных.
- HiGHS: **INFEASIBLE** (~4 с).

Пошаговая диагностика:

| Модель | Статус |
|--------|--------|
| Только назначение | OPTIMAL |
| Назначение + ресурсы (без y) | OPTIMAL |
| + ресурсы с y_j | OPTIMAL (если y=1) |
| + планы узлов | **INFEASIBLE** |

То есть данные читаются правильно, но **совокупность ограничений по узлам** в нашей формулировке не совместима. В MPS те же Plan_g заданы как **пары G/L с одинаковым RHS** (равенство), но связь переменных с узлами может отличаться в деталях, не восстановленных из txt без PDF постановки.

### MPS (эталон)

```

```

Задача **большая**; HiGHS за 10 минут может не доказать оптимальность, но **находит допустимое решение**.

## 8. Структура MPS (краткий разбор)

По файлу `model.mps`:

- **~59 702** бинарные переменные: **76** — `y_j`, остальные — разреженные `x_ij`
- **1160** ограничений типа E — по одной VM
- **304** ограничения L — ресурсы (76×4)
- **25 пар G/L** — планы узлов (равенство Plan_g)
- **1** ограничение G — миграция (≥ 582)
- Остальные L — конфликты и служебные связи

Целевые коэффициенты: **`β · c_j`** для `y_j`, **`β · c_ij`** для `x_ij`.

## 9. Как пользоваться блокнотом

1. `julia install_pkgs.jl` — один раз.
2. Установить ядро IJulia (см. раздел 3).
3. Открыть `Lab1_VM_Placement.ipynb`.
4. Выполнить ячейки сверху вниз.
5. Для **гарантированного численного ответа** раскомментировать ячейку с `solve_mps(...)` или запустить `run_lab1.jl`.

После `optimize!` и `has_values(model)`:

- `extract_solution` — словарь размещений, число активных серверов, сколько VM остались на месте;
- графики — histogram VM по серверам и pie «миграция».

## 10. Ограничения и рекомендации

1. **Время:** ставьте `time_limit` 600–3600 с; задача NP-трудная.
2. **Сдача:** для отчёта достаточно MPS + HiGHS + найденное Z.
3. **Модель из txt:** если преподаватель требует именно сборку из файлов — сверьте ограничения узлов с PDF «Постановка задачи»; возможно, Plan_g относится к другой величине (не сумма `c_j y + c_ij x`) или нужны неравенства с α.
4. **PDF** из Downloads в репозиторий не копировался — при расхождении ориентируйтесь на `model.mps` как эталон.
